**Architecture.** A `local_agent/` package split into `cli`, `agent`, `llm`, `tools`, `permissions`, `memory`, `project` and `security`, with central config and error handling. It needs nothing beyond the Python standard library. PyPI was blocked here, so I dropped `rich` and wrote a plain terminal UI instead.

**How it works:**
- **Agent loop:** each model call becomes a tool call that is schema-checked, risk-rated, approved by you if needed, executed, and fed back to the model with its real result. It stops on iteration, time or token limits, repeated identical calls, repeated failures, Ctrl+C or a model error, and always says why.
- **Tools:** paged file reading, exact-match edits that require reading the file first, write, move, delete, `.gitignore`-aware search (ripgrep or a Python fallback), and git status/diff.
- **Commands:** they get timeouts and output caps. Ctrl+C kills the running command, and I confirmed this in a real terminal. Environment variables that look like secrets are removed before a command runs.
- **Models:** Ollama and OpenAI-compatible servers. It checks whether the model supports native tool calling and falls back to a text-based protocol if not. An unreachable server or missing model gives a clear message, not a stack trace.
- **Evidence report:** built only from recorded results. It lists changed files, commands and exit codes, and flags untested changes, a failing last test run, and files changed by commands.
- **Undo:** files are snapshotted before the agent's first change. `/diff` shows changes, and `/undo` reverts them but skips any file someone else edited since. Interrupted tasks can be resumed with `/resume` or `--resume`.

**Memory.** Project facts carry a verified/unverified flag, user preferences are global and need your approval, and there is task history and saved sessions. Everything is stored as versioned JSON per project and redacted for secrets. `/memory`, `/memory search`, `/memory forget` and `/memory clear` let you inspect and delete it. Memory goes into the prompt labelled as reference data, not instructions.

**Permissions.** Four modes: `plan`, `ask` (default), `auto` and `full`. Each action is rated by risk: read, create, edit, destructive, uncertain command, network, privileged, sensitive file, or blocked.
- Deletes, network access, sensitive files (`.env`, keys) and privileged commands ask even in `full` mode.
- A few catastrophic commands are always refused, such as `rm -rf /` and `curl … | sh`.
- The model has no tool that can approve its own actions.
- A config file inside the project is never read, so a repository can't change your permissions.
- With no interactive terminal, anything needing approval is denied.
